# Knowledge Context V2

架构与核心约束见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

V2 把个人知识库重新定义为“个人上下文引擎”。M1 已打通 AI 对话、文件解析、事件、候选记忆、用户编辑与审核、冲突处理、审核撤销、历史版本恢复和上下文组装，原有 V1 保留在仓库根目录。

## M1 完成范围

- 来源内容先成为候选记忆，不会未经确认污染长期上下文。
- 用户可在确认前修改候选表述和重要性，并选择新增、合并、替代或拒绝。
- 最近一次审核可以撤销；合并撤销通过补偿版本完成，不改写历史。
- 任意历史版本可以恢复为新的当前版本，完整保留变更轨迹。
- 候选提取默认使用本地规则；可显式启用模型 Provider，超时或失败时自动回退。
- 同一套生命周期支持 SQLite 本机保存和可选 PostgreSQL；进程内实现用于单元测试。
- AI 工作区支持多轮对话，以及 PDF、DOCX、TXT、Markdown、CSV、JSON、HTML 上传；单个文件上限 10 MB。
- 项目助手显示实际使用过的已确认记忆；用户输入中的长期信息先进入待确认区，文档内容不自动变成个人记忆。

## 从首页开始

新版首页直接展示资料库，支持按名称搜索、按文件类型筛选、勾选资料后点击“问这些资料”。右上角可上传文件；每轮最多 5 份、单份 10 MB，超出数量会明确拒绝本次选择而不静默漏传。原文引用使用右侧抽屉，支持历史版本和下载。

- **问我的资料**：上传 PDF、Word 或文本 → 选择资料（不选即检索项目全部资料）→ 提问 → 点击 `[1]` 核对原文。第一问可以是：“这份文档主要讲什么？哪些要求已确定，还有哪些问题没明确？”
- **继续我的项目**：输入目标、决定或最新进展 → 获得结合已确认背景的回答 → 点“审核待确认记忆”，确认哪些内容以后继续使用。也可点“记住一件事”直接确认保存。
- **接着上次聊 / 历史对话**：打开以前的对话继续提问。对话用途保持固定；换用途请返回首页另开一段。
- 对话会先保存问题、再保存回答和引用。刷新页面会恢复当前对话；服务中断未完成的回答最多等待约 150 秒后可重试。未发送的输入草稿尚不保存。

聊天、记忆、候选、审核记录及版本保存在 `.data/context.sqlite`；文件及其版本保存在 `.data/documents.sqlite`。
无需安装数据库。所有数据仍是本机单用户数据，没有跨设备同步或登录隔离。调用 AI 时本轮需要的内容会发送给所配置的模型提供方；本机保存不代表完全离线。
已有 PostgreSQL 配置继续用于记忆，对话和资料仍存 SQLite；两种记忆库之间不自动迁移。切换配置前请备份。

本机存储采用事务及并发版本校验；记忆部分以完整状态快照保存，适合当前个人使用规模，不代表通过大规模负载验收。
历史对话最多列出最近 100 段；更早记录仍在数据库，已知对话地址仍可打开。尚无界面搜索、删除和导出对话。

## M2 资料库与原文引用（本地版）

需要 Node.js 24（使用内置 SQLite）。上传资料会持久保存到 `v2/.data/documents.sqlite`，
服务重启后仍可检索。可通过 `KNOWLEDGE_DATA_DIR` 修改数据目录；数据目录已排除在 Git 外。
原文件、每次上传的版本、解析文字和片段在同一事务中保存。备份时停止服务并复制整个 `.data` 目录。

使用方法：首页“问我的资料” → 上传文件 → 展开“资料库”检查原文 → 勾选资料或检索全部 → 提问。
回答中的 `[1]` 可打开对应版本的原文片段。资料列表支持上传新版、查看历史和下载各版本原文件。
删除会逻辑移出全部版本，后续检索、预览和下载均不再返回；历史聊天仍可保留已经显示的答案。
资料在回答期间发生更新或删除时，本轮回答被拒绝，提示重新提问。

“个人助手”和“仅依据资料”分开：后者不把个人记忆或历史模型回答作为证据，
文档内容也不再自动提取成个人记忆，避免资料删除后留下隐式副本。

当前边界：本机单用户；项目过滤不是登录授权。检索是中文二元词/英文词的关键词匹配，
尚非语义向量检索；一次最多选 20 份资料、召回 12 个片段（每片段约 1200 字符）。
单文件解析保留前 100,000 字符，超过会提示部分解析，原文件完整保留。
引用定位到解析片段与字符区间，不提供 PDF 页内高亮或表格结构还原；扫描件 OCR 尚未启用。
引用编号会校验，但不代表已经自动证明回答的每个结论都正确，仍需原文验收。

验证命令：`pnpm test`；启动本地服务后执行 `node scripts/check-m2.mjs http://127.0.0.1:3317`。
后一命令会调用已配置模型，使用独立测试项目及虚构内容，并在结束后移出本轮测试资料。
验收结果与剩余用例见 [docs/M2-ACCEPTANCE.md](./docs/M2-ACCEPTANCE.md)。

## 运行界面预览

项目未配置 PostgreSQL 时使用本机 SQLite，首次初始化三条此前已确认的项目背景，不会在每次启动时重复添加：

```powershell
pnpm install
pnpm dev
```

访问 <http://127.0.0.1:3000>。对话、资料和记忆在服务重启后仍保留；升级前已经丢失的进程内数据无法自动找回。

未配置 AI 模型时，工作区会明确显示“本地模式”：输入、文件解析、记忆检索和候选提取仍可验证，但不会伪装成模型生成回答。

## 启用 AI 回答

可复用 V1 的 Hugging Face 配置：

```dotenv
HF_TOKEN=...
HF_MODEL=Qwen/Qwen3-32B
```

也可以连接任意兼容 Chat Completions 的服务：

```dotenv
AI_CHAT_URL=https://your-provider.example/v1/chat/completions
AI_CHAT_API_KEY=...
AI_CHAT_MODEL=...
```

所有密钥只在服务端读取，不会发送到浏览器。复制 `.env.example` 为 `.env.local` 后重启服务即可生效。

## 可选 PostgreSQL 记忆存储

Docker 配置预留 pgvector 扩展，但当前资料检索仍是 SQLite 上的关键词匹配，没有上线语义向量检索。

需要 Docker Desktop：

```powershell
docker compose up -d
Copy-Item .env.example .env.local
# 将 .env.local 的 DATABASE_URL 设置为示例中的 PostgreSQL 地址。
pnpm db:migrate
pnpm dev
```

默认数据库端口为 `54329`，避免占用本机常见的 `5432`。

`pnpm db:migrate` 会按文件名顺序执行 `drizzle/*.sql`，并在数据库内用
`knowledge_migrations` 记录已应用迁移，重复执行是安全的。

## 可选的模型候选提取

默认不调用外部模型。只有设置以下服务端环境变量后才会启用：

```dotenv
MEMORY_EXTRACTION_ENABLED=true
MEMORY_EXTRACTOR_URL=https://your-provider.example/v1/chat/completions
MEMORY_EXTRACTOR_API_KEY=...
MEMORY_EXTRACTOR_MODEL=...
```

接口需兼容 Chat Completions JSON 结构。模型异常、返回格式错误或 20 秒超时都会自动回退到本地规则，来源事件会记录实际使用的提取方式。

## 项目助手的记忆链路

```text
用户对话、会议结论或项目说明
  -> Context Assembler 检索本轮相关的已确认记忆
  -> AI 使用本轮输入和已确认记忆生成回答
  -> events 保存原始输入
  -> memory_candidates 提取候选，不直接进入长期记忆
  -> 用户选择新增 / 合并 / 替代 / 拒绝
  -> memories 保存当前有效投影
  -> memory_versions 保留每次确认后的历史版本
  -> context_snapshots 保存可复现的上下文快照
```

资料问答是独立链路：文件解析与切片 → 保存文档及版本 → 关键词检索 → 仅依据证据回答 → 校验引用与版本 → 保存对话。文档不会沿上面的链路自动写入个人记忆。

```

如需执行 PostgreSQL 集成测试，请配置名称包含 `test` 的专用数据库：

$env:TEST_DATABASE_URL = "postgres://.../knowledge_v2_test"

```

## 已知不足与下一步

- 文档内的“动作/面试话术”与“待测试、待上线”说明可能冲突，综合总结仍可能漏掉限制。引用编号校验不能替代语义事实核查。
- 旧阶段和新阶段指标需要分别保留日期、样本和分母；正文版本与入库版本不是一回事。
- 复合问题中部分缺少依据时，目前可能整题拒答，没有充分输出可回答部分。
- 规则候选提取可能把问句当偏好，或拆掉“虚构测试”的限定；用户确认流程降低误写风险，但识别逻辑本身仍需改进。
- OCR、账号权限隔离、自动脱敏、大规模性能和反馈优化队列尚未完成。

后续先加强事实状态、冲突和拒答评估，再按瓶颈引入混合检索、事件时间线、项目状态更新及受控 Agent 工作流。详见 [项目复盘](../docs/PROJECT_REVIEW.md)。

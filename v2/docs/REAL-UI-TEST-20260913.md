## 需要优先修复的问题

### P1：跨句限定丢失，虚构内容形成无条件偏好候选

复现输入：

> 我偏好回答先给结论，再给依据。这是实机验收的虚构偏好，请提取为待确认记忆。

实际生成两条：

1. 偏好：我偏好回答先给结论，再给依据。
2. 事实：这是实机验收的虚构偏好，请提取为待确认记忆。

第一条丢失测试限定，第二条是操作说明而不是值得长期记住的事实。模型回答本身理解了“虚构”，但候选提取没有保持一致。

代码证据：`src/lib/memory/service.ts:135` 按标点拆句，逐句匹配关键词；`这是` 可触发 fact。当前没有跨句限定/否定/引用范围关联。

本轮人工把第一条改为“仅用于实机验收：回答先给结论，再给依据。”后确认；第二条拒绝。未修改产品提取逻辑。

期望：保留完整限定，或跳过虚构/示例内容；不把操作说明单独建议为稳定事实。建议新增否定、假设、引用他人及示例语境回归集。

### P1：问句被当成偏好，还默认建议合并

复现输入：

> 你记得实机验收场景下，我希望你怎样组织回答吗？

实际候选：

> 你记得实机验收场景下，我希望你怎样组织回答吗。

页面类型是“偏好”，识别把握82%，和已确认记忆匹配度22%，主按钮却为“合并为新版本”。普通查询没有提供新偏好，若直接接受可能把有效偏好改写成问题。

代码证据：`src/lib/memory/service.ts:95` 以“我希望”等短语判断偏好；135–158行拆句时去掉问号，再统一补句号；217–236行相似度达到0.12即进入候选匹配，只要存在匹配就默认建议合并（除替代提示词分支）。

期望：先判断用户是在陈述还是提问；查询不生成候选。关联程度低不应默认建议合并，实际合并应检查语义一致性、限定和增量信息。该错误候选保留在测试实例的“待确认记忆”中，未执行合并。

相关对话：`224e7a33-b1c9-445e-ab8f-8cb0d34304ce`。

### P2：回答中的 Markdown 未格式化

实际回答中的 `**不会**`、`**先给结论，再给依据**` 原样显示。当前组件按纯文本与引用标记分段渲染，不做 Markdown 渲染。影响可读性，不影响本次存储和引用核验。

## 独立核验

运行 `node scripts/check-ui-evidence.mjs http://127.0.0.1:3318`，此脚本仅读取通过页面产生的数据，不创建或删除资料：

- 4份独立资料、5份原始版本文件；下载字节的 SHA-256 与对应本地原文件逐一相同。
- 6段对话、18条消息；共9个引用记录的文档版本、片段ID、原文和字符区间均与库内原文一致。
- 4条已确认记忆（3条初始化背景加1条人工修正的测试偏好）。被拒绝的说明不在已确认记忆中。
- 重启后重复核验通过。

这些结果仅证明本轮样本，不代表用户18项用例全部验收。损坏/加密/超大文件、扫描件OCR、权限隔离、隐私脱敏、并发、反馈闭环、真实私人面试资料等没有在本轮页面实测中覆盖；此前接口测试不能替代这些实机结论。
